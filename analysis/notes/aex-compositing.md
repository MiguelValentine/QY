# AEX 像素预处理与合成边界

## 范围与证据

本文聚焦 `himgtile("res$ToolTips.ale")` 使用的 AEX 路径：颜色/GIF 平面预处理、帧记录偏移及当前可见的绘制调用。证据来自 `fbase.dll` 静态反汇编、`objsys.dll` 内置 `TOOLTIPS.ALE` 资源和现有 Go 解析结果；没有运行原版客户端，也没有声称已恢复完整逐像素合成。

相关路径与材料：

- [`newtip-background-call.md`](newtip-background-call.md)：`himgtile` 分派、背景模式 `0x13` 和图片资源加载。
- [`tooltips-resource.md`](tooltips-resource.md)：AEX 资源身份、两张 GIF 平面、三条描述符及 Go 端帧切分结果。
- [`aex-frame-mapping.md`](aex-frame-mapping.md)：FBase `#69`、`#77`、`#72` 的参数及帧块偏移写入。
- [`fbase.annotated.asm`](../disassembly/fbase.annotated.asm)：FBase `#69` 位于 `0x100296b0`，`#436` 位于 `0x10023380`，`#439` 位于 `0x10024350`。

这些是静态证据和离线资源解析结果，不是对原生绘制输出的观察。

## 已确认的预处理

FBase `#69` 的像素循环从 `0x10029980` 附近开始。每像素读取一个透明度字节和一个并行的 16 位颜色值。可见规则如下：

| 输入条件 | 处理结果 |
| --- | --- |
| alpha `> 0xF0` | alpha 写为 `0xFF` |
| alpha `== 0x11` | alpha 改为 `0x10` |
| `0x70 < alpha < 0x90`，且颜色分量近似值之和 `< 0x50` | alpha 写为 `0x11`，并设置后续特殊处理状态 |
| 其他 alpha | 保持原值 |

第三条由 `0x100299ce–0x10029a08` 支持：函数从 16 位颜色字计算三个分量近似值并求和，低于 `0x50` 时写入 `0x11`。具体分量扩展与常规按位扩展公式并不等同；实现应以指令序列为准，不能直接套用标准 RGB565 alpha 混色公式。`0x11` 是该预处理阶段产生的特殊命令/状态值，不是已经确认的普通透明度。

行编码器 `0x1002d160` 在特殊模式下把连续 `0x11` 编成 `A0..BF` 命令段，命令不携带对应的原始 `u16` 颜色。现有 [`ale-row-oracle.json`](../evidence/ale-row-oracle.json) 与行编码笔记验证了这一点。因此只凭该行命令无法从像素流重建特殊像素颜色；其最终绘制效果仍须由后续消费端证据决定。

## 帧与绘制路径

`#69` 以 24 字节步长读取 AEX 描述符并将六个 DWORD 传给 `#77`。参数流与 `#77` 写入新帧块的代码表明，描述符末尾的两个 DWORD 经裁剪增量修正后写入帧块 `+0x10/+0x14`。这是偏移字段被保存的直接证据，但本身不证明多个帧会互相拼接，也不证明偏移就是目标 DIB 的直接坐标。

对于 `TOOLTIPS.ALE`，资源中有 3 条描述符；Go 侧按已恢复的尺寸和偏移记录得到帧尺寸 `20×30`、`8×30`、`14×30`，偏移依次为 `(-1,0)`、`(0,0)`、`(0,0)`。`himgtile` 的对象路径会将资源存为背景模式 `0x13`。因此可以确认加载结果包含三张带独立偏移的帧图像，不能仅据帧尺寸或 `himgtile` 名称断言它们按 `x=0,20,28` 横向连续拼成 42 像素背景。

`#69` 在处理 AEX 像素前调用 `#439`（`0x10024350`），实参之一为 `1`。后续已确认虚表 `+0x0c` 清空图像字段、`+0x04` 调用 `#436` 重建图像，再由 `#344` 将保存的旧图像转换到新格式。默认加载为格式4（RGB565），转格式1时对补零通道作整数平均；全部65536个输入已经原生函数仿真验证，见 [透明度平面转换](aex-alpha-conversion.md)。邻近的 `SetDIBitsToDevice`（`0x100236a6`）和 `BitBlt`（`0x1002370b`）证明存在 GDI 传送/复制路径，但不证明它们对 `0x11` 执行何种逐像素操作。

## 当前可实现范围与未知

可实现并已有 Go 覆盖的范围是：读取支持的 AEX 外层、解密并解码单帧 GIF/JPEG 平面、按默认模式转换到 RGB565、透明度平面再转为单字节灰度、复现上述 alpha 预处理、依据描述符矩形裁剪，并保存帧偏移及特殊标记。对应代码在 `internal/ale/aex.go`、`internal/ale/aex_pixels.go`、`internal/ale/aex_frames.go`；该范围输出的是待绘制帧数据，不是原版合成结果。

目前不能从已留存的静态证据确定：

- 普通 alpha 是否参与混色、混色发生在哪个阶段，以及其整数舍入和通道顺序。
- 特殊 `0x11` 像素最后是跳过、写入键色、抖动/遮罩处理，还是由其他路径处理。
- 三帧之间的绘制顺序、偏移的坐标基准、画布宽度，以及是否存在横向拼接或覆盖。
- GDI 传送/复制调用与最终 AEX 渲染消费路径的关系。

`0x1001ab60` 一带的格式分派和 `#344` 的格式转换不能替代上述缺失证据；RGB565 到 BGRA 的格式转换结果也不是 alpha 混色 oracle。当前不应将 `AEXFrame.Pixels` 直接绘制为普通 RGBA，也不应把特殊标记近似成 alpha 值 `0x11` 后套用常见 source-over 公式。
