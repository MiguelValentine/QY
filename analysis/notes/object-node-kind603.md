# `kind=603` 对象节点静态路径

## 范围

本记录追踪 `CLIENT/index.fcc` 中 `kind=603` 节点的 parser 分支，以及其节点字段值在 `0x10065fa0` 中对应的执行分支。证据来自 `analysis/disassembly/objsys.annotated.asm` 和本地 PE `.text` 跳表字节；未运行原版客户端，不代表观察到游戏对象创建或窗口初始化。

## 已确认

- parser 将 `kind=603`（`0x25b`）送到 `0x1001081b`。分支在 `0x1001081b–0x1001081f` 调 `0x10011f10`，将当前节点对象 `+4` 设为 `0x0a`。`0x10011f10` 直接把参数写到 `ECX+4`。
- 该 parser 分支读取 `<...>` 中的标识符；错误路径含有 “need classname” 提示（`0x1001083d–0x10010862`）。后续可选地处理基类样式的附加部分，并要求 `>` 与 `{`，随后调用 `0x1000f820` 处理块（约 `0x10010867–0x10010974`）。这是语法/节点构造路径，不是对象实例构造证据。
- `0x10065fa0` 取首个栈参数，经 FBase #525 或 #520 取得执行对象到 `EDI`；它从 `EDI+4` 读取跳表索引（`0x10066032–0x10066045`），并设 `ESI=EDI+8`。跳表地址为 `0x10067bf0`；索引 `0x0a` 的槽 `0x10067c18` 内容为 `0x100679f5`，因此 parser 节点字段 `0x0a` 对应此执行分支。这里的关联基于相同的节点字段/分派值，不涉及 FBase #799 的 tag。
- `0x100679f5` 先以 FBase #803 校验容器形状：第一个元素的 tag 为 `4`，接下来的三个元素 tag 为 `3`；失败则报 “New VAR format err!”（`0x100679f5–0x10067a10`）。随后它通过 FBase #785 读取索引 `0` 和 `2`，对索引 `0` 的值调用 FBase #788 取哈希，再将哈希与索引 `2` 的值传给 `0x10065890`（`0x10067a15–0x10067a44`）。
- `0x10065890` 前段先比较全局对象数 `0x10121cd0` 与 `10000`。只有数量大于该阈值才进入 `0x100658c3–0x10065ab3` 的对象列表诊断路径（日志含 `FObj::s_ObjNum`、`kind/total`）；数量不超过阈值时，控制流跳到 `0x10065ab6` 正常查找/创建路径。
- 正常路径先将第一个参数 `[EBP+8]` 传给 `0x1005f070`。该函数经 FBase #302 使用全局工厂/注册对象 `0x10121e84`、`0x10121e54` 解析并调用可用工厂；返回对象非空时，caller 跳至 `0x10065b14`。`0x1005f070` 将输入值写入返回对象 `+0x0c`，并在第一条工厂路径上调用返回对象 vtable `+0x2c` 的方法；若两种工厂解析路径均不可用则返回空（`0x1005f070–0x1005f108`）。这些是对象创建工厂路径的静态证据，但具体 C++ 类名及工厂接口语义尚未恢复。
- 工厂未返回对象时，`0x10065890` 从当前上下文开始沿对象 `+0xa8` 父链查找；对每个有 `+0xb8` 类表的上下文，以输入类名调用 `0x1000a4a0`。匹配后从类表记录读取关联对象/字段，并以提取出的两个值递归调用 `0x10065890`（`0x10065ac9–0x10065b12`）。因此，父链上的类记录也会经过同一个工厂/查找路径。
- 找到/创建到对象记录后，函数将第一个参数写入返回记录 `+0x10`（`0x10065b14`）。第二个参数 `[EBP+0x0c]` 是可选的初始化块：非空时，对其 `+4` 调 FBase #522；若块容器存在，就以 `ECX=ESI`、该块对象为首个参数、其余四参数为 0，递归调用 `0x10065fa0`（`0x10065b17–0x10065b3c`）。这是执行器对对象初始化块的直接递归调用证据；块是否执行由 caller 是否传入非空第二参数决定。
- 初始化递归返回后，`0x10065890` 从记录 `+0x18` 关联对象取三个字段，并复制到对象 `+0xa4` 所指结构（`0x10065b41–0x10065b99`），随后返回 `ESI`（`0x10065b9c–0x10065baf`）。若第二参数为 nil 或其 `+4` 容器为空，则跳过初始化块执行，直接返回/结束该处理。
- opcode `0x0a` 分支在 `0x10067a15–0x10067a44` 读取容器索引 `0` 的类名哈希和索引 `2` 的值，以此作为 `0x10065890` 的两个实参；后续再处理索引 `1`（`0x10067a53` 起）。因此类名/基类解析与初始化块的实际关联由这两个值在执行期容器中的布局决定；本笔记不将索引 2 的字段语义扩展到未追踪的其他 parser 形态。

## 未知与边界

- parser 的 `<标识符>`、可选基类、块数据如何编码到执行期容器索引 `0/1/2`，仍未逐字段闭环；因此不能把上述执行期两个参数的语义推广到所有对象语法形态。
- `0x1005f070` 使用的 FBase #302 工厂对象、返回记录的精确 C++ 类型及对象 `+0x0c/+0x10/+0xa4` 字段类型仍未知。
- 已确认非空的第二参数可触发递归执行初始化块；但目标脚本在运行期是否提供该参数、该对象工厂调用是否成功，以及构造对象是否足以使游戏进入可交互状态，仍需 runtime/完整调用链证据。
- 本记录说明存在静态对象工厂与初始化块执行路径，不等于观察到原版成功创建入口对象或进入游戏。
