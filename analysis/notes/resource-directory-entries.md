# 资源目录条目展开

证据为 `objsys-disassembly.json` 中
`ev_79268ca8fa4f56c3fa122adeae94d4774f186500c9d5deb328525b66ac46cbaf`
和 `fbase-disassembly.json` 中
`ev_5fc95fa046397bf605b945fbf373993a52efed99a223a6fc52164b61aa8a1e0a`。
这里描述静态反汇编，不代表目录已下载或游戏已进入。

`objsys!0x1001a2f0–0x1001a31e` 遍历文本读取器提供的行，跳过长度不超过
3 字节的行，其余调用 FBase #688，以逗号拆分。Go 复用已恢复的
`fbase.NextWord`，保留该函数对引号、首部注释及裁剪的处理。

第一个字段是路径，可引用前一条已经展开的路径：

- 普通字段直接使用。
- `+` 分支（`0x1001a34a–0x1001a396`）用 #682 解码下一个字符，
  取前一路径的相应长度前缀，再追加从第三个字符开始的后缀。
- `*` 分支（`0x1001a39b–0x1001a41f`）先用 #682 解码下一个字符，
  得到前缀长度编码占用的字符数，再用 #682 解码这些字符。
  从前一路径取该长度的前缀，追加剩余后缀。
- 原生 #710 在长度超出旧字符串时会扩容。Go 对此返回格式错误，
  不把未初始化的内存字节解释成路径。

`0x1001a425–0x1001a44a` 保存展开后的路径供下一条引用，同时把资源目录
所在的目录字符串追加到路径前。后续三次 #688/#681 提取数值
（`0x1001a450–0x1001a4b9`）。这些值在 `0x1001a4e4–0x1001a4fc` 分别写入
记录偏移 `+0x14`、`+0x1c`、`+0x18`；当前不猜测字段业务名称。

Go 的 `parseResourceDirectory` 返回独立的路径字节和这三个数值，
对截断的编码、超范围回引和缺失的数值字段明确报错。
它只完成条目解析；全局记录表的替换、缓存有效性、下载和文本容器解码
属于独立调用链，不能用此解析器的测试通过代替这些行为。
