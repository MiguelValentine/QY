# 资源目录6位数字编码

## 字符表初始化

`analysis/disassembly/fbase.annotated.asm` 中 FBase #691 位于 `0x1000db50`，由 `0x10004554` 调用。初始化先将 `0x100911d0`（#715）的256个DWORD清零，再以循环变量 `i=0..63` 生成字符并写入 `table[character]=i`（`0x1000dba4–0x1000dbd4`）。生成规则是：

- `i=0..9`：`'0'..'9'`，值0..9；
- `i=10..35`：`'A'..'Z'`，值10..35；
- `i=36..63`：从 `'_'` 连续到 `'z'`，值36..63。因而这段包含 `_`、反引号及小写字母。

其余字节的表项为初始化时写入的0。它们并非拒绝输入，而是在解码中贡献数值0。

## 解码语义

FBase #681（`0x1000e1f0`）读取C字符串首字节并查#715；空串返回0。随后逐字节执行 `value = (value << 6) + table[ch]`，直到NUL。除首字节外，遇到ASCII空格时直接返回当前累计值，不处理空格及其后缀。运算保留32位，因此左移溢出按uint32回绕。

FBase #682（`0x1000e230`）采用同样的首字节处理和累计规则，第二参数是有符号计数。计数小于等于1时仍返回首字节映射值；计数大于1时最多处理前`count`个非NUL字节。此入口不将空格作为结束符，空格查表得到0后照常参与移位累积。输入NUL会提前结束。

实现对Go切片边界作显式限制；原生接口接收NUL结尾指针，没有切片长度。两个函数保留原生32位回绕语义，不将未知字符作为错误处理。

## 目录记录的路径键

`objsys!0x1001a4c2–0x1001a506` 先将完整路径交给 `0x100185a0`，再将返回的32位值作为键传给全局容器 `0x100b6d64` 上的 `0x10018860`。`0x100185a0` 先复制路径并调用 FBase #702；#702 直接调用 `CharLowerBuffA`，所以参与后续计算的路径先按当前 ANSI Windows 大小写规则转为小写。之后它调用 FBase #195：该函数扫描并折叠 `..\\` / `../` 形式的上级路径段，并对四组静态字符串执行 #708 替换，再返回规范化字符串。最终调用 FBase #858 对该字符串计算32位值；此处传入的标志为0，哈希本身不再执行额外大小写转换。

`0x10018860` 对全局有序表按两个整数键查找；本调用传入哈希和固定的配对键（0），未见路径字节比较。若键已存在，它返回既有记录的对象指针；若不存在且创建标志为1，则插入记录。随后调用点无论新旧记录都会给记录路径字段重新赋值，并覆盖 `+0x14`、`+0x1c`、`+0x18` 三个字段。因此，同一规范化路径重复出现会复用并覆盖同一条记录；不同路径若32位哈希相同，也会命中并覆盖同一条记录，容器没有第二阶段的完整路径碰撞校验。

大小写差异通常会在路径键计算前被折叠，但精确转换规则依赖 Windows `CharLowerBuffA` 的 ANSI/区域设置行为；不能将其泛化为对所有字节和区域设置都完全相同的 Unicode casefold。规范化与散列还会将路径身份压缩为32位键，存在哈希碰撞别名风险。
