# `imgex.frame` 成员与帧几何

## 结论

`imgex` 的成员哈希 `0x6c181c97` 对应字符串 `frame`。原生 setter
`0x1002c19f` 只接受整数；值与对象当前字段不同时，将整数写入对象
`+0x6d`，再调用虚函数 `+0x84` 更新图像状态。getter
`0x1002c50f` 从 `+0x6d` 读回整数。构造路径没有显式初始化 `+0x6d`，
因此本记录不推断原生新对象初值；Go 实现将其清零为 `0`。

布局更新函数 `0x1002bc90` 在资源已就绪时，以 `+0x6d` 为帧索引调用
FBase `#50`。帧表越界时，`#50` 返回空矩形。Go 保存传入索引，并在
索引无效时将当前帧宽高和偏移映射为零；这里不拒绝越界值，也不表示原生
对象一定采取相同的所有后续状态处理。

## 原生证据

- setter `0x1002c19f` 检查值类型是否为整数，读取整数后与对象字段比较；
  相等则不更新，不等则写 `+0x6d` 并调用虚函数 `+0x84`。
- getter `0x1002c50f` 将对象 `+0x6d` 作为整数返回。
- `StringTableHash("frame")` 为 `0x6c181c97`。
- `0x1002bc90` 在资源存在且就绪时将当前索引交给 FBase `#50`。FBase
  `#50` 按索引访问帧块，以偏移和宽高构造矩形；索引越界时输出零矩形。
- 构造函数 `0x1002bb60` 初始化图像对象的其他字段，但没有显式写入
  `+0x6d`。不能仅凭分配内存或 C++ 常见约定给原生默认值定性。

反汇编位置见 `analysis/disassembly/objsys.annotated.asm` 中
`0x1002c19f`、`0x1002c50f`、`0x1002bc90`，以及
`analysis/disassembly/fbase.annotated.asm` 中 FBase `#50`
（`0x100261f0`）。帧矩形字段细节另见
[`img-startup.md`](img-startup.md)。

## Go 映射与验证

`internal/objsys/imgex.go` 暴露 `frame` 的整数读写。加载新资源时 Go 将帧
索引设为 `0`，并从对应帧刷新宽、高和偏移；切换有效帧也刷新这些几何字段，
但不覆盖对象位置。帧变化标记 `Dirty`，同值写入不产生变化；非整数写入报错。
当前映射覆盖位图单帧以及 `ImageResource` / ALE 帧元数据。

测试使用真实资源 `CLIENT/in/img/map/root/land_02.ale`：帧 0 为
`130×99`；帧 1 为 `275×202`，偏移 `(-79,-57)`。测试还覆盖默认 Go 值、
getter、同值写入、超范围索引的空几何和非整数拒绝。资源解析和几何状态
测试不证明帧已绘制到屏幕；绘制路径、动画调度和最终画面仍未由此恢复。

`Dirty` 是 Go 实现中的状态通知，不应与原生对象 `+0x58` 等状态位直接等同。
