# 桌面资源路径分派静态追踪

## 范围与证据边界

本文只记录 `CLIENT/com/kele8com.fcc` 中两个 `pdesktop` 成员调用及其在 `CLIENT/objsys.dll` 中的静态分派路径。地址是模块首选装载基址 `0x10000000` 下的 VA。依据为本地 FCC 解码文件和 `analysis/disassembly/{objsys,fbase}.annotated.asm`；未执行原版程序，也未访问脚本中出现的服务器。

FCC token 转储在 `0x362` 处包含对 `pdesktop.0x112e4b8f` 的调用，实参为 `URL` 与 `"kele8com"`；在 `0x39e` 处包含对 `pdesktop.0xaf665c57` 的调用，实参为 `URL + "files_dir.dz"`。这只确定脚本向宿主分派器提供的成员哈希和参数，不据哈希猜测成员名或业务效果。

## `0x112e4b8f` 分支

成员分派函数从 `objsys!0x10060dbe` 附近取得成员哈希。比较 `0x112e4b8f` 后，控制流在 `0x10060fd1` 开始处理该分支（反汇编文件 `analysis/disassembly/objsys.annotated.asm`，约第 128872 行起）。

- 分支以 FBase #636 初始化局部值，随后以 FBase #770 对调用方传入的值执行成员/参数读取；该 API 的完整高层语义不在本文中命名。
- 成功路径对两个局部值分别调用 FBase #646，再把得到的值传给 FBase #215（`objsys!0x1006102b–0x10061041`）。
- FBase #215 的返回值经 `test eax,eax` 转为 `0` 或 `1`，再调用 FBase #748 写入分派调用关联的 VM 值（`0x10061044–0x10061050`）。
- 分支随后清理局部值并跳到公共出口 `0x10062470`（`0x10061056–0x1006107b`）。公共出口将 native dispatcher 的 `EAX` 清零返回。该状态码与前面写入 VM 值的 `0/1` 是不同通道，不能把 native `EAX=0` 当成脚本结果。
- 参数读取失败路径以状态码 `2` 退出（`0x10061016–0x10061026`），也不能据此判断脚本层表达式结果。

FBase #215（`fbase!0x10008eb0–0x1000904c`）先检查首个字符串是否以 `"http://"` 开头，再检查表项数是否已达到 `0x13`；容量已满时立即返回 `0`，不会尝试替换已有项。容量未满时，它去掉源字符串开头的 `"http://"`、转小写并将 `/` 换成 `\\`，再遍历全局记录表；记录步距为 `0x20c`。命中已有规范化源键时调用 FBase #839 并使用 `"Replace PathMaping http://%s as %s"` 文本，随后覆盖该记录的第二个字符串；未命中时调用 FBase #839 并使用 `"PathMaping http://%s as %s"` 文本，再把规范化源键和目标复制到新记录。新增/替换路径返回 `1`，前缀不符或容量已满返回 `0`。据可见调用与数据写入，这是进程内映射配置的新增/替换，不是网络请求或下载；本函数片段没有出现网络或文件 I/O 调用。

FBase #748（`0x10014280`）按目标 VM 值首 DWORD 的类型分派；type `1` 路径把栈上整数与 `0xF0A0` 异或后写入值字段，并设置类型码 `1`。此处仅能确认分派器把本次比较的布尔化 `0/1` 交给该值写入辅助函数，完整脚本表达式消费语义不在此扩展。

## FBase #216 / #217 路径细节

以下是 `analysis/disassembly/fbase.annotated.asm` 中 #216（`0x10008b90`，约第 12220 行起）与 #217（`0x10009090`，约第 12692 行起）的静态控制流观察。字符串对象辅助函数仍以导出序号标记，不据其名称推断额外语义。

- #216 将输入复制到局部缓冲区，从末尾反向寻找最后一个 `/` 或 `\\`。找到时，第一个输出为分隔符之前的目录并追加一个反斜杠，第二个输出为分隔符之后的部分；末尾分隔符对应空 basename。没有分隔符时，第一个输出清空，第二个输出复制完整输入（`0x10008bdd–0x10008c41`）。
- #217 对首 7 字节精确比较小写 `http://`；不匹配时直接返回 `EAX=0`（`0x100090b3–0x100090e5`）。通过检查后，先删除这 7 字节、按 `CharLowerBuffA` 转小写，再把 `/` 替换为 `\\`（`0x100090e6–0x1000910d`）。
- 随后 #217 把该字符串交给 FBase #195。#195（`0x10007c80`）先复制字符串到临时缓冲区及全局缓冲区 `0x10090c70`，扫描 `..\\` 片段并从累积路径中移除前一个目录，最后返回该全局缓冲区。#217 将返回指针通过 #639 赋回其字符串对象（`0x1000910b–0x10009123`）。这是路径段规整，不是 URL 哈希。
- #215 的源参数也在保存前删除 `http://`、小写化并把 `/` 转成 `\\`；它调用 #195 后忽略返回值，复制的仍是此前处理后的局部字符串（`0x10008f1a–0x10008f5e`）。所以一般 URL 前缀形式可对齐，但含 `..\\` 的源键与 #217 规整后的请求路径可能不相同；本样本控制流没有把 #195 的返回值保存为映射源键。
- #215 先检查容量计数 `>= 0x13` 并立即拒绝，然后才准备键值及遍历现有项（`0x10008ee1–0x10008efc`）。因此容量满时重复键也不会进入替换分支。表未满时，规整后的源键逐字节比较；匹配项覆盖目标，未匹配则追加。表步距为 `0x20c`，源键和目标均有 `0x104` 字节槽位。
- #217 对规整后的输入取最后一个点号，把扩展名与无扩展名 stem 分开，再按最多 `0x13` 项遍历映射表并检查源键前缀（`0x1000913a–0x1000923f`）。命中且扩展名为小写 `dll` 时，按 `'%s%s\\%s.dll'` 构造根目录、映射目标和去掉映射前缀及扩展名的余串（`0x10009241–0x10009291`）。其它扩展走 `'%s%s\\%08X.fch'`；#648 先把扩展名与去掉映射前缀后的余串拼成哈希输入，再调用 FBase #858（`0x10009293–0x100092c6`）。#858 的 Go 对应实现及原生对照见 `internal/symbol/hash.go` 与 `analysis/tools/oracle_fbase_string_hash.py`。
- 未命中映射时，#708 先将 `:` 替换为 `_`、将 `\\` 替换为 `@`，然后 #693 在开头插入 #220 根路径（`0x100091d6–0x10009206`）。样本 `0x1005f2c0` 内容为 `C:\\FancyWork\\`，这里只能称静态默认值，不能断言是运行时实际安装目录。有效 HTTP 输入的公共收尾返回 `EAX=1`；以上路径构造不等于文件存在、下载成功或 DLL 已加载。

## 另一资源参数分支的边界

第二个 FCC 调用的 hash `0xaf665c57` 在同一成员分派器中由 `0x10061b92–0x10061b9e` 单独比较，命中后跳至 `0x10061c82`，与本节 `0x112e4b8f` 分支是不同处理块。它检查输入 VM 值类型码为 `3`，经 FBase #808 取出字符串相关指针，再调用 FBase #646 取值并传给 `objsys!0x1001a1a0`（约第 129779 行起）。此处仅用于确认控制流分离；不为 `0x1001a1a0` 或 hash `0xaf665c57` 补充未经证实的语义名。`objsys!0x1005e5d0` 的调用点不在这两个 hash 分支中，故不将它并入本文入口链。

## 对“进入游戏”的意义

本链只闭合了 FCC 向 `pdesktop` 提交参数、`objsys` 按 hash 分派及 FBase 辅助函数处理值。它没有证明用户认证、服务端响应、资源完整性校验、游戏大厅初始化或成功进入可操作游戏场景。复现该启动入口仍需分别恢复这些后续状态转换，并以与当前样本匹配的运行时证据验证；本笔记不把静态分支分析当成“可以进入游戏”的实现完成度证明。
