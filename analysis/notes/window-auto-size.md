# `wnd` 自动宽高属性静态核对

## 范围与结论

本文核对 `CLIENT/index.fcc` 首个 `<wnd>` 类体中的 `autowidth=100`、`autoheight=100`，以及 `CLIENT/objsys.dll` 对应成员登记、setter、`wnd` 构造字段和即时矩形更新路径。证据来自本地 FC0A token 输出、`analysis/disassembly/objsys.annotated.asm` 和仓库 `symbol_lookup` 工具；没有运行原版客户端。反汇编地址为装载基址 `0x10000000` 下的 VA。

`objsys.dll` 在 `wnd` 成员表中仅登记了这两个名称的 setter，没有在相邻登记序列中登记 getter。两个 setter 都要求对象 `+0xa8` 有父对象；成功时立即以父矩形宽高为基准计算百分比，并分别改写子对象的右边界 `+0x2c` 或下边界 `+0x30`，随后设置对象状态位。它们不直接创建/调整 OS 窗口，也不调用完整布局函数。`index.fcc` 中二者位于 `bk:=null` 之前。

## 脚本位置与符号候选

运行 `go run . tokens index.fcc` 后，首个 `<wnd>` 类体从 token 偏移 `0x320` 开始。其尺寸与自动尺寸语句为：

- `0x33e` 起：`size = Form.width, Form.height`
- `0x37a` 起：哈希 `0x924240e8 = 100`
- `0x392` 起：哈希 `0x8d603feb = 100`
- `0x3aa` 起：`bk := null`

使用本仓库工具执行 `go run ./analysis/tools/symbol_lookup 0x924240e8 CLIENT/objsys.dll CLIENT/fbase.dll`，返回 `CLIENT/objsys.dll` 文件偏移 `663808` 的字符串候选 `autowidth`；`go run ./analysis/tools/symbol_lookup 0x8d603feb CLIENT/objsys.dll CLIENT/fbase.dll` 返回文件偏移 `663796` 的候选 `autoheight`。哈希和字符串候选相符是名称线索，不单独证明属性绑定；绑定由下述原生成员表登记证据补强。

## 原生登记与构造默认

- `0x1004f445–0x1004f451` 将字符串地址 `0x100a2100`（`autowidth`）和回调 `0x1004ed80` 交给 setter 登记函数 `0x1004d470`；`0x1004f456–0x1004f462` 将 `0x100a20f4`（`autoheight`）与 `0x1004eec0` 同样登记为 setter。相邻代码没有为这两个名称调用 getter 登记入口 `0x1004d4d0`，故此处只能确认写访问器；不能假定脚本读取时能取回配置。
- `wnd` 工厂 `0x1005e1d0` 分配 `0xc8` 字节对象并调用构造函数 `0x1005d720`。构造函数接收所属对象并写入对象 `+0xa8`（`0x1005d773–0x1005d777`）；在 `0x1005d792–0x1005d79c` 清零对象 `+0x14` 起的 `0x69` 字节，其中包含初始矩形字段 `+0x24/+0x28/+0x2c/+0x30`；并在 `0x1005d7c1` 显式将自动布局配置指针 `+0x80` 置零。因此构造时宽高矩形初始为零，自动布局配置尚未分配。
- 两个 setter 首次成功时，如果 `+0x80` 为空，就调用辅助函数创建配置记录，并将该记录前 `0x24` 字节清零；后续 setter 复用同一记录。`autowidth` 的配置写在记录 `+0x0a/+0x0b/+0x0f/+0x13`；`autoheight` 写在 `+0x17/+0x18/+0x1c/+0x20`。

## Setter 计算与立即影响

`autowidth` setter `0x1004ed80`：

- 先检查接收对象 `+0xa8`；为空就返回失败。随后调用 FBase #768 从传入值按四个 tag 1 输出槽抽取整数。缺省槽依次为比例 `0`、偏移 `0`、下限 `1`、上限 `16000`；单个整数写比例，tuple 可依次覆盖这些槽。因此 `autowidth=100,-6` 表示比例 `100`、偏移 `-6`，下限和上限仍为 `1`、`16000`。
- 若比例字节非零，读取父对象宽度 `parent[+0x2c] - parent[+0x24]`，乘以比例并以整数运算除以 `100`，再加偏移；先应用下限、再应用上限，最后令子对象 `+0x2c = child[+0x24] + 结果`。所以 `100,-6` 的即时宽度为父宽减 6，随后受默认上下限约束；计算结果直接改写右边界。
- 成功路径在 `0x1004ee9c` 对子对象 `+0x48` 按位或 `0x2000`，在 `0x1004eea4` 写 `+0x58=1`，返回成功。这里确认的是字段被设置，不据此臆定两个字段的更高层命名。

`autoheight` setter `0x1004eec0` 对应执行相同形态的计算，四个输出槽默认依次为比例 `0`、偏移 `0`、下限 `1`、上限 `12800`。脚本值 `100` 写入记录 `+0x17`；若传入 `100,-6`，则偏移为 `-6`，其余边界仍使用默认值。比例非零时以父高度 `parent[+0x30] - parent[+0x28]` 乘比例并除以 `100`，再加偏移、依次应用下限和上限，最后令子对象 `+0x30 = child[+0x28] + 结果`。成功路径同样设置子对象 `+0x48 |= 0x2000`、`+0x58=1` 并返回成功。

Go setter 同时接受原生的整数和一至四个整数 tuple；空 tuple、非整数成员及超过四项会明确报错。超过四项时原生 #768 的稳定行为尚未恢复，因此没有按“忽略额外项”处理。

所以两个 setter 都是同步改写对象的矩形右/下边界，并保留当前左/上边界；在本脚本的 100% 参数下，计算依赖父对象当时的尺寸。静态路径没有显示它们递归调整子孙、触发实际窗口尺寸变化或调用通用布局器；父对象是否在之后改变以及其他布局路径如何消费 `+0x48/+0x58`，需要独立证据。

## 启动顺序与边界

FC0A token 顺序是 `size`、`autowidth`、`autoheight`，再到 `bk := null`。因此自动尺寸赋值先于 `bk` 赋值；这份静态证据不表示 Go 当前执行会在哪一个语句停止，也不证明本次计算得到的几何值已经绘制到屏幕。

## 主要证据位置

- `analysis/decoded/index/tmp.cod`：首个 `<wnd>` 及其 `size`、自动宽高和 `bk` token。
- `analysis/disassembly/objsys.annotated.asm`：成员登记 `0x1004f445–0x1004f462`；setter `0x1004ed80`、`0x1004eec0`；工厂与构造 `0x1005e1d0`、`0x1005d720`。
- 符号候选命令输出：`autowidth` 文件偏移 `663808`，`autoheight` 文件偏移 `663796`。候选字符串不替代原生登记代码证据。
