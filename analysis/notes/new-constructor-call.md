# new 的构造调用

## 原生证据

复用 `analysis/disassembly/objsys.annotated.asm` 和
`analysis/disassembly/fbase.annotated.asm` 的本地反汇编。

- 分派表基址 `0x1011d1d0`。`0x1001626b` 将无括号 new（990）的
  回调 `0x10016110` 写入 `0x1011e148`；`0x10016275` 将带括号
  new（991）的回调 `0x10014150` 写入 `0x1011e14c`。
- 带括号回调在 `0x10014177–0x100141c2` 先弹出已求值的实参和
  名称记录，再在 `0x100141e8–0x100141f3` 以所属对象和名称调用
  `0x10065890` 创建实例。实参求值因此早于工厂和类体初始化。
- FBase #788（`0x10012df0`）以 ECX 接收名称 VM 值，返回缓存的
  名称哈希；没有栈参数，普通 `ret` 返回。`0x10014259` 的
  `push 0` 是后续对象调用的标志参数，不是 #788 的参数。
- `0x10014259–0x10014268` 将标志0、实参指针、同名哈希和调用上下文
  传给新实例的 `0x1005ad10`。该函数先调用虚表 `+0x24`；
  状态为1时才在 `0x1005ae02` 继续脚本成员查找。
- 构造方法状态非0时，`0x1001426f–0x100142bc` 记录错误后继续。
  返回方法的值不替换实例：`0x100142df–0x100142ed` 写入结果的是
  实例指针及其 `+4` 标识。
- 无括号回调 `0x10016110` 创建实例后直接进入事件/返回阶段，
  没有同名方法调用。
- 两种形式均检查实例 `+8` 的 `0x100` 位，再调用
  `0x1005ab90(context, 0x376d2b34, nil)`。该哈希按项目名称算法
  对应 `OnCreate`；`0x10066219–0x1006622e` 在登记此成员时设置该位。
  事件 helper 在 `0x1005ac22–0x1005ac39` 将空实参指针转为空 VM 值，
  上下文保存在对象 `+0x90`，不是传入脚本函数的第一个实参。

## Go 行为与边界

解析器保留 `new` 的子节点为名称或名称调用；调用形态先在调用者环境
从左至右计算参数，再复用既有类构造路径，最后调用实例同名方法。
仅最终请求的类名触发构造方法，不自动调用所有基类同名方法。
无构造方法时仍返回实例；构造方法返回值被忽略。
成员表中登记的 `OnCreate` 在同名方法后执行，实参为空。

Go 对构造方法中的错误仍立即停止，保留未实现能力的诊断；没有仿照
原生把这些错误仅写日志后继续，以免把缺失实现伪装成初始化完成。
对象登记表目前属于 Go 宿主的跟踪设施，与原生表达式结果栈不同。
动态类名、名称槽中的显式宿主寻址及完整调用上下文仍未恢复。
