# `bk` 背景对象绘制路径

## 范围与证据

本文闭合纯色 `bk` 对象从已恢复的 `color` 状态到 FBase 绘制调用的静态路径，并记录绘制入口的可见门控。证据来自 `CLIENT/objsys.dll`、`CLIENT/fbase.dll` 的带注释反汇编及 [SYSTEM 背景颜色笔记](system-background-color.md)。未运行原版客户端；静态调用路径不代表实际观察到的游戏画面。

相关材料：

- [`system-background-color.md`](system-background-color.md)：`bk` 工厂、vtable、`color` selector 与 RGB565 值。
- [`newtip-background-call.md`](newtip-background-call.md)：`himgtile` 设置 mode `0x13` 的路径。
- [`aex-compositing.md`](aex-compositing.md)：AEX 预处理及尚未恢复的最终合成边界。
- [`objsys.annotated.asm`](../disassembly/objsys.annotated.asm)：绘制候选 `0x100443a0`、mode 分支 `0x10044b42` / `0x100446c6`、上层调用点 `0x10062630–0x10062926`。
- [`fbase.annotated.asm`](../disassembly/fbase.annotated.asm)：导出 `#319` (`0x1001d750`)、`#320` (`0x1001d850`) 与 `#384` (`0x10019fd0`)。

## 纯色消费

`bk` vtable `0x100a1b58` 的槽 4 指向 `0x100443a0`。此函数先检查对象 `+4` 的宿主上下文；空上下文会直接返回。常规路径基于宿主区域、对象尺寸及偏移字段计算绘制矩形；mode `0x0b` 另走一套使用对象 `+0xd0/+0xd4/+0xdc` 等字段的矩形计算（`0x100443dc–0x10044489`）。

进入 mode 分派前，函数通过 USER32 `UnionRect` 合并矩形，并调用 FBase `#366` 与 `#392` 准备/处理区域数据（`0x1004448a–0x10044505`）。随后从对象 `+0x20` 取 mode，经 `0x10045d40` 跳转表分派（`0x1004450b–0x10044517`）。跳表以 DWORD 索引；从 `CLIENT/objsys.dll` `.text` 节 `0x10045d40` 的原始字节核对，index 0 的 DWORD 是 `0x10045c79`；index 6 的目标 `0x10044b42` 属于另一条 mode 路径。这一区别很关键：`color` setter 写入对象 `+0x20=0`，所以它走 `0x10045c79`。

index 0 分支从背景对象 `+0xc4` 读取颜色，将其与矩形交给 FBase `#320`（调用点 `0x10045c79–0x10045ce9`）。FBase `#320` 的入口是 `0x1001d850`，它转调 `#319`（入口 `0x1001d750`）；`#319` 先通过 `#404` 获取目标像素地址和行跨度，再裁剪绘制范围。针对两字节像素的分支用 `rep stosw` 按矩形行写入颜色，其他像素宽度分支逐行调用 FBase `#384`（入口 `0x10019fd0`）；`#384` 按目标像素宽度写入颜色。反汇编范围分别是 `#320: 0x1001d850–0x1001d86e`、`#319: 0x1001d750–0x1001d847`、`#384: 0x10019fd0–0x1001a0a4`。结合 [SYSTEM 背景颜色笔记](system-background-color.md) 中 `color` 分支对 `+0xc4` 的 RGB565 写入，可确认纯色状态有一条通向 FBase 矩形像素填充逻辑的静态路径。FBase 的 `#404` 所取绘制目标如何连接到最终宿主窗口仍未在本笔记中追完。

mode `0x13` 是跳表 index 19，对应目标 `0x1004597a`，不是 `0x100446c6`；后者是 index `0x0d`。本笔记不据 `0x100446c6` 的调用参数推断 AEX 的混色行为。mode `0x13` 对应的图像/帧绘制细节不在本轮纯色路径范围内。

## 上层调用门控

`0x10062630` 是一个带状态检查的宿主更新路径，而不是无条件的绘制循环：

- 若对象 `+0x1c9e` 或 `+0x1ca0` 非零，立即退出（`0x1006264b–0x10062661`）。
- 之后读取宿主窗口句柄 `+0x1c64`；在其为空时改检查 `+0x1c68`。没有可用窗口时退出（`0x10062667–0x10062680`）。
- 通过 `GetClientRect` / `GetWindowRect` 计算宿主尺寸和偏移。尺寸非正时退出；与已保存尺寸比较，未变化时跳过后续重建/绘制路径（`0x10062689–0x1006271f`）。
- 满足后续分支条件时，通过对象 vtable 槽 `+0x10` 调用背景绘制候选 `0x100443a0`，再调用槽 `+0x14` 与 `+0x18`（`0x10062876–0x100628af`）。这些调用位于窗口调整及绘制相关更新路径中，不证明每次窗口消息都会绘制。

## 绑定记录标志与未知

在纯色 mode 0 的绘制路径中，没有发现读取宿主绑定记录 `+0x1c` 标志的指令。上层入口可见的是窗口更新状态 `+0x1c9e/+0x1ca0`、窗口句柄与尺寸判断；这些字段与 [背景 null 绑定笔记](background-null-binding.md) 所述的记录 `+0x1c` 不是同一地址上下文。

`0x1005ca40` 是 `bk` 构造器调用的基类初始化函数：它将 `+0x1c` 清零并安装 vtable `0x100a3244`；随后 `bk` 自身构造器在 `0x1004358c` 覆盖为 vtable `0x100a1b58`。原始 `.rdata` 字节表明基类 vtable 的直接方法目标包括 `0x1008943f`、`0x100428b0`、`0x10048dd0`（两个槽）、`0x10006000`、`0x1005e1b0`。在这组直接方法中没有发现读取基类对象 `+0x1c` 的消费者；最后一个目标 `0x1005e1b0` 转调 `0x1005cab0`，后者检查 `+0x18`，并在该字段非零时设置宿主对象 `+0x48` 的 `0x20` 位（`0x1005cad1–0x1005cad9`），没有读取 `+0x1c`。这是对该 vtable 直接目标的有界检查，不排除其他类、调用方或间接方法消费此标志。

静态观察闭合了纯色 setter 到 FBase 16 位矩形像素填充逻辑，但仍有边界：没有运行时证据确认绘制目标、可见窗口结果或绘制频率；通用区域处理及目标表面获取的完整含义仍未恢复；该路径也不证明 Go 移植版已经实现像素呈现。

## 可移植边界

Go 端可按明确状态复现 `color` 到 RGB565 的转换，并将裁剪后的矩形填充到本地帧缓冲区。可移植部分是矩形与 16 位像素填充逻辑；USER32 窗口裁剪、FBase 设备上下文/表面生命周期和 native vtable 调用不是可直接照搬的 Go ABI。应由 Go 窗口/渲染层明确提供目标帧缓冲区及裁剪矩形，不能把上述静态路径描述为已实现可见背景。
