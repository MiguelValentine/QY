# imgex 启动属性

## 工厂与继承

`CLIENT/objsys.dll` 的 PE image base 为 `0x10000000`。字符串 `imgex` 位于 RVA / 文件偏移 `669048`（`0xA3578`），所以 VA 为 `0x10000000 + 0xA3578 = 0x100A3578`。`analysis/disassembly/objsys.annotated.asm:0x1005F893–0x1005F8B5` 从工厂表查找该名称，空槽时写入工厂 `0x1002E370`。

工厂 `0x1002E370` 分配 `0x1BC` 字节并调用构造函数 `0x1002E070`。该构造先调用 `0x1002BB60`；`0x1002BB60` 调用 `wnd` 构造函数 `0x1005D720`，随后安装图像基类 vtable `0x100A0B38`。`imgex` 构造再安装 vtable `0x100A0CD8`。因此这里确认基类链包含 `wnd`，不是只凭对象尺寸推断。

## `src` setter/getter

`imgex` vtable `0x100A0CD8` 的 `+0x30` 项跳板 `0x1002E150` 跳到成员 setter `0x1002BEE0`。其中哈希 `0xA06413CF`（DLL 字符串候选 `src`）分支位于 `0x1002C1E3–0x1002C290`。它调用 FBase `#768` 抽取两个参数，声明的类型顺序是 tag `3`（字符串）和 tag `1`（整数）：字符串写入对象 `+0xCC`，整数输出用于后续资源查找；调用前还将对象 `+0x108` 作为抽取器的初值。由此支持脚本值 `(string path, int flag)`，不是单字符串 setter。初始整数槽为 `98`（构造函数将 `+0x108` 写成 `0x62`），但这不等于已证明脚本省略第二项时的完整默认行为。

setter 之后调用 `0x1002BE90` 清理旧资源。资源查找前先调用 FBase `#686` 检查 `+0xCC` 字符串；长度小于 1 时走提前返回。随后 FBase `#702` 调用 `CharLowerBuffA` 转换该字符串，再调用 FBase `#646` 取得已有字符串指针，空值时返回静态空串；这两个导出入口均为 `ret`（`C3`），调用点不传入显式参数。第二项乘 2 后作为参数传给 `0x1005FC30`。该 thunk 从当前资源上下文 `+0x1C90` 跳到 `0x10019B00`。`0x10019B00` 规范化资源名并依据传入整数的正负分流：非负走 `0x10019780`，负数走 `0x100190C0`；后续调用 FBase `#32` 获取资源对象。返回值写入对象 `+0x69`，返回资源的 `+0x10` 写入对象 `+0x6D`，然后调用对象 vtable `+0x84` 更新状态/布局。证据表明整数参与资源查找路径；它不是在此处直接写入缩放尺寸。

相同 vtable 的 getter 跳板 `0x1002E160` 跳到 `0x1002C330`；其 `src` 分支 `0x1002C527–0x1002C545` 从对象 `+0xCC` 取字符串并写回结果。构造函数 `0x1002BB60` 在 `+0xCC` 调 FBase `#636` 初始化字符串，故初始 `src` 为空。

## 尚未命名的语义

- `imgex` 工厂 VA、RVA 与文件偏移的关系已闭合：`0x100A3578 = 0x10000000 + 669048`。
- setter 接受 `(string, int)` 的结构、源字符串槽和资源读取路径已由调用点确认。
- 第二个整数实际影响 `0x10019B00` 的资源查找分流，但当前证据不足以给它命名为时长、帧数、缩放比例或缓存标记。默认 `+0x108 = 98` 也不足以确定该整数在脚本层省略时的最终行为。
- FBase `#702`、`#646` 的上述行为由 `analysis/evidence/pe-inventory.json` 的导出地址及反汇编交叉确认；`#85`、`#32` 在此链中的完整语义仍未命名。资源失败后原生对象如何处理也需结合更上层调用继续确认。

## 证据位置

- `analysis/disassembly/objsys.annotated.asm`：工厂登记 `0x1005F893`；`imgex` 工厂/构造 `0x1002E370`、`0x1002E070`；`wnd` 基类及图像基类构造 `0x1002BB60`、`0x1005D720`；setter/getter `0x1002BEE0`、`0x1002C330`；资源查找 `0x1005FC30`、`0x10019B00`；布局更新 `0x1002BC90`。
- `analysis/evidence/pe-inventory.json`：`imgex` 字符串 RVA 与文件偏移；FBase `#702` / `#646` 导出地址。
- `analysis/notes/window-auto-size.md`：`wnd` 工厂与构造入口交叉证据。

## Go 接入与验证范围

Go 已登记 `img` 和 `imgex` 工厂，复用 `wnd` 布局并保留 `src` 字符串、解码资源和本次整数参数乘二所得的加载参数。支持本地 JPEG、ALE 和已恢复模式的 AEX 帧准备：存在的本地文件在 `0x10019780–0x10019915` 通过 FBase #206 检查后返回成功，不进入网络排队。尺寸由当前帧或 JPEG 原始宽高更新。不把第二个参数解释成缩放比例；非本地资源的完整排队、缩放缓存和绘制尚未恢复。图像完成事件延迟到对象更新期，详见 [img 启动记录](img-startup.md)。

FBase #768 的既有参数抽取证据与 setter 的局部初始化共同支持单字符串调用沿用默认值 98；显式第二项仅写局部输出，没有回写对象 `+0x108`，因此下一次单字符串调用仍沿用构造默认值。对于未知参数形态或其他图像格式的尺寸更新，Go 明确报告未恢复能力。

2026-10-16 较早图形进程止于 `index.fcc:0xd7c` 的 ctrl；当前入口测试已越过 `0x1acc` 的带参数 `new land(...)` 和 land `pointmode`，推进至 `0x1670` 的 `CreateObj` 调用（哈希 `0x0e9c89f6`）。land 设为位置 `(272,206)`，src 为真实 `in/img/map/root/land_02.ale`，AEX 帧准备为 `130×99`、`275×202`，第二帧偏移 `(-79,-57)`。真实 Logo 的单独 `OnLoaded` 更新仍在 `index.fcc:0xf38` 的移动绑定处停止。没有图像绘制或进入游戏的证据。
