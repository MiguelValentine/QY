# Path mode 1 初始化与更新

## 结论

selector `0x69a34356` 与 `0xf6f99e51` 都初始化 path mode 1。两者都用 FBase #770 和格式 `ddd(5)u(0)` 读取两个坐标、一个默认值为 5 的除数和可选完成事件；若明确提供的除数小于 1，则归一化为 3。`0x69a34356` 先将前两个值作为增量传给 owner 虚表 `+0x6c`，再把目标位移取负；`0xf6f99e51` 不移动 owner，也不取负目标。两者都将路径索引 `+0x3c` 清零并设置 mode `+0x20` 为 1。相关分派与初始化见 `objsys.dll` 的 `0x10048577–0x10048705` 和 `0x10048798–0x100487ef`。

## owner 的 `+0x6c`

三个相关构造路径均指向同一槽函数：

- `img` 通过 `0x1002bb60` 构造，写入 vtable `0x100a0b38`（`0x1002bb95`）。
- `imgex` 通过 `0x1002e070` 先调用 `img` 构造，再写入 vtable `0x100a0cd8`（`0x1002e0a5`）。
- `Wnd` 构造器 `0x1005d720` 写入 vtable `0x100a3270`（`0x1005d745`）。

PE `.rdata` 的 RVA 与文件偏移映射表明，这三个 vtable 的 `+0x6c` 项分别位于文件偏移 `0xa0ba4`、`0xa0d44`、`0xa32dc`；三处原始 DWORD 均为 `0x1005c5e0`。`0x1005c5e0` 接收两个整数增量，分别累加到 owner 的 `+0x14`、`+0x18`；若 `+0x50` 非零则更新 `+0x1c` 缓存，并设置 `+0x48` 的 `0x8000` 标志。因此，mode 1 初始化时该虚调用会按 selector 的前两个整数平移 owner 的逻辑坐标。

## mode 1 更新

`0x10048c70` 的五个小端 DWORD 依次为 `0x10048b37`、
`0x10048b89`、`0x10048c23`、`0x10048af0`、`0x10048a1f`，
对应 mode 0–4。必须按原始字节读取，不能将反汇编器把表数据误解出的
指令边界当作表项边界。

更新函数 `0x10048a0a` 通过跳转表分发 mode；mode 1 对应入口 `0x10048b89`。`+0x24/+0x28` 是从零开始的累计相对位移，`+0x2c/+0x30` 是目标相对位移；窗口当前坐标不作为插值游标。当除数 `+0x40` 不大于 1 时，它直接将累计位移设为目标；否则每轴计算 `(target-current)/divisor`，x86 有符号除法向零截断，并按目标方向额外增减 1，保证每帧继续前进。更新后将累计位移的本帧差量传给 owner 虚表 `+0x6c`，并保存累计位移；两轴都到达目标时调用完成函数 `0x100484b0`。

完成函数将 path `+0x1c` 置 1；若 `+0x58` 非零，则通过 `0x1005ab90` 向 owner 派发完成事件。

FBase `#506` 实际只出现在 mode 2 入口 `0x10048c23–0x10048c6d`，该模式不属于本次 Go mode 1 实现。mode 2 读取 `path +0x60` 的节点表，并把输出交给 owner 虚表 `+0x64`。其他 selector `0xea78cc18` 和 `0x69e43664` 分别初始化 mode 2 和 mode 4；静态反汇编只说明各自的状态初始化，不证明其已在目标运行时执行。

以上是对随仓库 `CLIENT/objsys.dll` 的静态分析；它说明二进制中的控制流，不代表实际运行时已观察到动画完成事件。
