# FBase #768 参数抽取

## 结论

`objsys!0x1004e290` 是 `size` 属性 setter（属性登记见 `objsys!0x1004f180`）。它把传入值交给 `FBase!#768`，为两个目标参数各提供 tag `1` 和一个输出槽；只有 #768 返回值至少为 2 时，setter 才调用对象虚表 `+0x70` 写入这两个结果。

这个调用接受至少两个成功抽取值，不要求返回数恰好为 2。该事实不等于已经证明额外 tuple 元素会被忽略：#768 的 tuple 循环按源 tuple 长度迭代，而不是按调用点的 `2` 截断；调用点只显式传入两个 tag/输出槽。对长度大于 2 的输入，第三轮会继续读取后续抽取描述，静态调用点没有提供其定义，因此额外元素的结果未知，不应在 Go 中按“忽略多余元素”或“完整支持任意长度”臆造行为。

## 静态证据

### 调用约定与成功条件

- `analysis/disassembly/objsys.annotated.asm:103257` 起是 `0x1004e290`。它保存输入值指针后调用 `FBase.dll!#768`（`0x1004e2a9`）。
- 调用参数依次包含输入值、立即数 `2`、立即数 `1`、一个栈地址、另一个立即数 `1` 和第二个栈地址（`0x1004e296–0x1004e2a8`）。据此可确认调用点为两个结果槽请求 tag `1`。
- setter 将返回值与 `2` 比较并以 `jge` 接受（`0x1004e2b2–0x1004e2be`）；少于 2 时返回失败。成功后将两个局部结果推给虚表 `+0x70`（`0x1004e2be–0x1004e2cf`）。
- #768 入口位于 `analysis/disassembly/fbase.annotated.asm:30624`，地址 `0x100143b0`。其栈上的正数参数 `2` 只在 tuple 分支入口处检查是否 `<= 0`（`0x10014472–0x10014481`）；tuple 主循环的终止条件是迭代索引与源容器长度比较（`0x10014493–0x10014497`、`0x10014573–0x10014585`），不是该参数值。

### 单值与 tuple/list 形态

- #768 先检查输入对象首 DWORD 的类型。类型 `6` 进入专门的容器抽取分支（`0x100143ba–0x100143c5`），从对象 `+8` 指向的结构读取元素数，并逐项比较元素类型、执行转换、写入输出槽。每成功一项递增返回计数。
- 非类型 `6` 输入不会走该逐元素展开循环；它必须匹配调用提供的单值目标 tag，才走单值分支。因此本 setter 的两个 tag `1` 输出描述不会把单个整数扩展成两个参数；单值至多贡献一个结果，达不到 setter 的 `>=2` 门槛。
- 元素地址计算中，容器类型 `6` 与 `0x1a` 有专门的内联元素寻址分支（`0x1001449d–0x100144c6`）。这说明 #768 的逐项路径认识两种容器存储布局；但入口仅对顶层类型 `6` 分派到该循环，不能据此断言顶层 `0x1a` list 也会展开。顶层 `0x1a` 的 setter 行为在此调用约定下未被证明。
- 对 tuple 多于两个元素的情况，循环没有 `count == 2` 的硬上限，且 setter 只显式布置两个 tag/输出槽。额外循环读取什么、是否因类型/指针检查而提前终止，取决于调用栈后续内容；现有静态证据不足以定义第三项及之后的稳定语义。

### tag 1 与整数转换

- tuple 抽取先要求元素内的类型 DWORD 与对应 tag 描述完全相等（`0x100144c6–0x100144ca`），然后按 tag 跳转。tag `1` 分支调用 `FBase!#778` 并把 EAX 写到输出槽（`0x100144e1–0x100144fd`）。
- `FBase!#778` 位于 `0x10012200`：类型 `1` 返回值字段并执行 `xor 0xF0A0`（`0x10012215–0x1001221d`）；类型 `8` 则走浮点转整数路径（`0x10012202–0x10012210`）。但 #768 在逐项转换前仍比较实际元素 tag 与请求 tag；本 setter 请求 tag `1`，不能据 #778 单独支持类型 `8` 推断它会接受浮点元素。
- 因此 Go 实现若表示 FBase 内部编码整数，不能把 tag `1` 的字段当普通未经转换的有符号整数；至少该转换路径含 `^ 0xF0A0`。#778 对类型 `8` 的转换属于其他 tag 场景，不应混入本 setter 的 tag `1` 规则。

## 适用于 Go 移植的边界

1. `size` setter 需要两个 tag `1` 结果；单值输入不足以通过成功门槛。
2. tag `1` 使用 #778 的整数编码转换，具体字段解释不能用普通类型断言替代。
3. 顶层 tuple 类型 `6` 会按元素循环；顶层 list 类型 `0x1a` 尚无展开证据。
4. 返回阈值是至少 2，而非恰好 2；但第三项及之后不应视为已定义、可忽略或安全支持。

以上结论来自静态反汇编，不代表已观察到原生运行时对异常长度或畸形值的处理。
