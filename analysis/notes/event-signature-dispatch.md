# 创建事件的签名查找

证据来自保存的 `objsys.annotated.asm`、`fbase.annotated.asm`，
不是原版客户端动态运行。

## 原生路径

`new` 和 `CreateObj` 的 `OnCreate` 分支传空参数指针给
`objsys:0x1005ab90`。`0x1005ac22–0x1005ac39` 将该指针转换为
类型0的空 VM 值，并不构造两个整数或传一个显式的 null 参数。

普通事件分派未被对象虚表处理时，进入 `0x1005a3f0`。
`0x1005a427–0x1005a441` 调用 FBase `#761` 取得实参类型签名，
随后通过 `0x1000acd0` 查表。其内部 `0x1000ac40` 比较记录的
名称哈希、标志和签名三个 DWORD；找不到返回零，外层在
`0x1005a44c` 返回状态1（未处理），不会执行同名但签名不同的函数。

`#761` 位于 `FBase:0x10013010`。非 tuple 输入返回类型码低四位；
少于8项的 tuple 将各项类型码依次左移4位拼接，8项及以上则使用
`0xf0000000 | 元素数` 的签名。匹配记录之后还会经过
`objsys:0x1000ab10` 的数量检查和 FBase `#804` 的类型检查。
签名用于查找，不能用它替代全部参数校验。

`index.fcc` 的 `btn_index` 包含 `OnCreate(int,int)`，
而该实例自动创建事件的实参为空，因此此声明不是该次事件的匹配项。
原版查找路径没有给这两个参数隐式补零的证据。

## Go 修正

事件分派按已恢复的参数数量和类型选择同名声明；同名后续声明保留
此前函数链，以便零参数和有参数的事件处理函数同时存在。
无匹配返回未处理；匹配后执行函数体时遇到的错误继续返回，
不能将资源、成员或语法缺项吞掉。

自动 `OnCreate` 使用同一内部事件分派 helper，并保留启动入口的
位置和步数预算。公开的逐帧事件入口仍重置单次执行步数。
当前没有声称恢复普通函数调用的完整重载表、未知参数类型、
原生签名冲突或所有修饰符。

修正后真实 Go 入口越过历史 `index.fcc:0x2924`，完成三个
`btn_index` 图片对象的构造，继续到 `index.fcc:0x2f1e` 的
`autopos` 绑定（成员哈希 `0xdddd0b92`）。图片总数由15变为17。
这属于执行链推进，尚未证明图像呈现或进入游戏。

后续已恢复 `autopos` 与命名控制器，当前初始化边界为
`index.fcc:0x46b8` 的 `atomsys` 工厂。最新运行见
[启动记录](startup-progress.md)；上文 `0x2f1e` 保留为事件签名修正时的历史边界。
