# `ctrl` 的 alpha 初值与首帧边界

## 结论

对本次指定的 `wnd` 成员绑定 `ctrl`（成员名哈希 `0x11b4b1fa`）及调用参数 `("alpha", 0, 255, 50, 0, 1)`，静态证据支持以下结论：

- objsys 注册表中的 `"ctrl"` 指向工厂 `0x10048430`。工厂分配 `0x6c` 字节对象，并以所属对象为参数调用构造函数 `0x10047df0`。
- `0x10047efc` 的哈希分支 `0xb3ef61e9` 按格式 `"uddd(1)d(0)d(-1)u(0)"` 解析绑定名称、起止值及控制参数。给定绑定名和数值后，初始化状态中的当前值为起始值 `0`，终值为 `255`，步进值为 `50`。
- 该分支在构造期同步把属性名和值交给所属对象的虚函数表 `+0x30` 槽；在这个调用中属性名为 `"alpha"`，值为 `0`。因此，**初始绑定提交值可以确定为 0**。
- `ctrl` 虚函数表 `0x100a1cfc` 的 `+0x08` 槽为更新函数 `0x10048240`。它先等待计时条件满足，再推进当前值；按这组参数，首个推进值为 `50`，不会由解析阶段直接提交。
- **首个实际绘制帧使用 0 还是 50，静态证据不能确定。** 现有证据没有闭合所属对象的更新与绘制调度顺序，也没有实际运行时首帧观测。

## 证据

### 工厂与对象生命周期

原生登记过程在 `0x1005f6db` 以字符串地址 `0x100a35dc`（内容 `"ctrl"`）查找/写入工厂表，空表项会登记回调 `0x10048430`。参见 [objsys.annotated.asm](../disassembly/objsys.annotated.asm#L126893)。

工厂 `0x10048430` 分配 `0x6c` 字节，并调用 `0x10047df0` 构造；构造函数调用基类初始化 `0x1005ca60`，安装 vtable `0x100a1cfc`，初始化对象成员与计时状态。参见 [构造函数](../disassembly/objsys.annotated.asm#L94022) 和 [工厂回调](../disassembly/objsys.annotated.asm#L94584)。

在 `CLIENT/objsys.dll` 的 `.rdata` 中，地址 `0x100a1cfc` 开始的函数指针依次包含 `0x10047ee0`、`0x100428b0`、`0x10048240`；因此更新函数位于 vtable `+0x08`。对应原始节数据可由 `objdump -s -j .rdata CLIENT/objsys.dll` 在 `0x100a1cf0` 行核对。析构入口 `0x10048490` 委派到 `0x10047e70`；析构过程释放计时成员 `+0x60`、名称/值成员 `+0x28`，并调用基类析构 `0x1005cab0`。参见 [析构入口](../disassembly/objsys.annotated.asm#L94590) 与 [析构实现](../disassembly/objsys.annotated.asm#L94071)。

### `alpha` 绑定与初始提交

`0x10047efc` 比较成员哈希 `0xb3ef61e9` 后进入专用分支。该分支使用格式 `"uddd(1)d(0)d(-1)u(0)"` 将绑定名称及控制参数解析到对象字段；接下来根据起始值、终值和方向建立初始状态。给定调用中的当前值来自起始值 `0`。参见 [ctrl 参数解析与分支](../disassembly/objsys.annotated.asm#L94108) 和 [alpha 分支状态初始化](../disassembly/objsys.annotated.asm#L94243)。

初始化分支将当前值封装后，读取所属对象指针（`ctrl+0x04`），并通过所属对象的 vtable `+0x30` 槽提交属性值。解析得到的名称位于 `ctrl+0x24`，当前值在首次提交时为 `0`。参见 [初始值提交路径](../disassembly/objsys.annotated.asm#L94306)。

### 定时步进

更新入口 `0x10048240` 先检查当前时钟与对象记录的截止时间；截止时间未到时直接返回。满足计时条件后，它按状态机选择更新路径，使用配置步进推进当前值，并在值变化时再次通过所属对象 vtable `+0x30` 槽提交属性。对 `0 → 255`、步长 `50` 的配置，首个递增提交为 `50`。参见 [更新入口与计时门槛](../disassembly/objsys.annotated.asm#L94394) 和 [更新值提交路径](../disassembly/objsys.annotated.asm#L94458)。

## 未闭合事项

- 该证据证明的是构造期属性提交与后续定时更新，不证明绘制调用与更新调用在首帧中的先后顺序。
- 未观察到实际运行时首帧，也未由此确定首个绘制帧读取的是同步提交值 `0` 还是更新后的值 `50`。
- 所属对象 `vtable+0x30` 的接收方类型及属性最终如何影响绘制，不属于本笔记已证实范围；此处不据此推断像素透明度或画面效果。

## Go 接入

`internal/objsys/controller.go` 实现 `0xb3ef61e9` 的 loop 模式；尚未恢复
loops、timer 等其他 selector。参数顺序为属性名、起值、终值、步长（默认1）、
间隔（默认0，归一化到1毫秒）、边界次数（默认-1）、可选完成事件名称。
负步长按原生 int32 取负，零步长改为1；降序时保存原始起值作为当前值并交换上下界。
未实现的属性或 selector 明确失败，不能仅保存参数后跳过。

`0x10048291–0x100482c7` 使用严格大于/小于判定边界，因此精确到达端点不立即
递减次数；下一次越界才钳回端点、反向并递减。完成后先提交端点，再按
`0x1004839c–0x100483aa` 派发事件。Go 事件共用普通脚本函数执行逻辑，
保留函数定义时的 receiver 和闭包，异常仍向调用者返回。

FBase #874 位于 `0x100117a0`，可回退 `GetTickCount`；Go 用窗口会话的单调
经过毫秒映射到32位时钟。每次 update 只推进一步并在旧截止时间上累加间隔，
不按跨越的毫秒数无限补帧。对象树更新快照与窗口后端属于移植设计，不声称
已验证原生首帧调度或像素输出。
