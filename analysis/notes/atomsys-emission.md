# atomsys 发射参数与随机数

本文依据 `CLIENT/objsys.dll` 的静态反汇编，并与当前 `internal/objsys/atomsys.go` 对照。没有观察原版客户端运行；反汇编能说明控制流和调用顺序，但不单独证明画面效果。

## 普通粒子发射

- 对象成员分派在 `objsys.annotated.asm:41403-41418`；成员哈希 `0x6d166ec0` 跳到 `0x100204c3`，由此进入普通发射处理。
- 以下栈偏移以 `0x100200c0` 完成 `sub esp,0x24` 和保存 EBX/EBP/ESI/EDI 后的 ESP 为 `E`。#770 调用参数按 x86 调用约定从栈顶读取；因此输出指针的语义顺序是调用前 `push` 顺序的反序。`0x100204c3-0x100204f5` 的八个目标地址及格式顺序如下：

  | 格式项 | 目标地址 | 反汇编中的后续用途 |
  | --- | --- | --- |
  | arg1 | `E+0x14` | 发射坐标 x；传给粒子初始化 |
  | arg2 | `E+0x38` | 发射坐标 y；传给粒子初始化 |
  | arg3 | `E+0x18` | 粒子数量循环上限 |
  | arg4 | `E+0x2c` | 随机速度基值 |
  | arg5 | `E+0x44` | 速度随机除数，下限夹到 5 |
  | arg6 | `E+0x3c` | 寿命基值；随机寿命加此值 |
  | arg7 | `E+0x40` | 粒子阻尼，传给粒子初始化 |
  | arg8 | `E+0x28` | 固定分裂阈值；负值转自动随机阈值，格式默认标记为 `-1` |

- 地址校验：调用前按顺序 push 的目标为 `[E+0x28,E+0x40,E+0x3c,E+0x44,E+0x2c,E+0x18,E+0x38,E+0x14]`；反转后即上表。每条 `lea` 的地址按执行时 ESP 计算，后续每次 `push` 都使 ESP 减 4。
- `0x10020506-0x10020513` 将一个发射除数下限夹到 5；`0x10020525` 起按计数循环，计数不大于 0 时不创建粒子。
- 每个粒子先取一次随机数并除以该除数，余数加基准速度；再取一次随机数，对对象角度范围取余并加角度起点（`0x10020530-0x1002055b`）。
- `0x10020562-0x100205b8` 根据一个参数是否为负选择分裂值路径：负值走随机路径，以另一个发射参数计算 `参数/3+3` 的余数除数，再从该参数扣除余数和 5；非负值走另一条路径。随后取随机数对 900 取余并合成寿命值。粒子初始化由 `0x1001f940` 完成（`0x100205a1-0x100205e0`）。
- `0x1001f940` 的 ABI 为 ECX=this，栈参数依次是 x、y、speed、angle、life、drag、split；其函数体在 `objsys.annotated.asm:40735-40764` 按此顺序读取并写入粒子字段。调用者先压 split、drag，再压 life、angle、speed、y、x，和该 ABI 一致。
- 从随机调用可见，普通发射每粒子消耗速度、角度和寿命三次随机数；arg8 为负、需要自动计算 split 时再消耗一次。该路径没有运行时随机序列验证。

## 轨迹发射

- 成员哈希 `0x646b5c41` 在 `0x100200d8` 分派到 `0x10020207`。该路径调用 FBase #768 读取七项轨迹参数。以下同样以完成函数序言后的 ESP 为 `E`。调用前按顺序 push 的输出目标为 `[E+0x20,E+0x30,E+0x3c,E+0x1c,E+0x40,E+0x44,E+0x38]`，每个目标前另 push 长度 1；#768 从调用栈按相反顺序消费类型/目标对，因此语义参数顺序为：

  | 参数 | 目标地址 | 反汇编中的用途 |
  | --- | --- | --- |
  | arg1 | `E+0x38` | 目标端点 x |
  | arg2 | `E+0x44` | 目标端点 y |
  | arg3 | `E+0x40` | 每个采样点的粒子数量，下限夹到 1 |
  | arg4 | `E+0x1c` | 随机速度基值 |
  | arg5 | `E+0x3c` | 速度随机除数，下限夹到 10 |
  | arg6 | `E+0x30` | 成功发射路径后不再读取 |
  | arg7 | `E+0x20` | 粒子阻尼，传给粒子初始化 |

- #768 实参压栈序列是 `target1,1,target2,1,...,target7,1,count,source`；栈顶顺序因此为 `source,count,1,target7,...,1,target1`。七个目标地址来自 `0x10020207-0x10020239` 的 `lea`，逐项计算时需包含每次压入目标和长度整数。
- 上次坐标位于对象偏移 `+0xd188/+0xd18c`。新旧坐标相同则直接返回；否则计算两轴差的平方和并取平方根作为距离（`0x10020259-0x100202a2`）。
- 距离小于 4 或大于 1000 时直接转函数尾声，不取随机数、不保存新坐标。此控制流也见 [atomsys-trail-emission.md](atomsys-trail-emission.md)。
- 距离通过后，粒子数量下限夹到 1，速度随机除数下限夹到 10（`0x100202bd-0x100202dc`）。沿线按步长 13 插值取点（`0x100202f0-0x10020324`），每点按数量创建粒子。
- 每个轨迹粒子按顺序取随机速度、随机角度、分裂相关值、寿命（`0x10020330-0x1002039c`），并另取两个 `%10-5` 的位置偏移（`0x1002039f-0x100203cb`）。arg7 阻尼值在 `0x10020382` 读取；arg6 的 `E+0x30` 槽在解析后未被该发射分支引用。粒子初始化仍由 `0x1001f940` 完成，调用者压栈顺序为 split、drag、life、angle、speed、y+offset、x+offset，和构造函数 ABI 相符。
- 只有越过发射循环后，才将新坐标写回 `+0xd188/+0xd18c`（`0x1002041e-0x10020428`）。相同坐标及距离门限分支均不会更新该状态。

## 随机数

- `objsys!0x1008787f` 从随机状态读取 32 位值，执行 `state = state*0x343fd + 0x269ec3`，保存新状态并返回 `(state >> 16) & 0x7fff`（`objsys.annotated.asm:177578-177580` 及后续指令）。
- 当前 Go 的 `Desktop.nextAtomRandom` 使用相同 LCG 和输出位段（`internal/objsys/atomsys.go:88-91`）。
- 原生启动初始化在 `0x10009d7a-0x10009d84` 将空指针传给 `0x100878a1`，取其返回值，再传给状态写入函数 `0x10087872`。前者调用 `GetSystemTimeAsFileTime`，将 FILETIME 减去 Unix epoch 偏移并除以 `10,000,000`，返回 Unix 秒（`0x100878a1-0x100878d9`）；后者把参数写入 RNG 状态 `+0x14`（`0x10087872-0x1008787e`）。调用点位于该初始化分支在 `0x10009d6f` 之后、后续初始化继续之前。
- 因此该启动路径将 Unix 秒作为 LCG 初始状态。Go 端按当前 Unix 秒转换为 `uint32` 可匹配这一静态证据；这不代表已运行原版验证。其他可能的间接状态修改及运行时随机序列尚未穷尽。

## 对照边界

- Go 的 `emit` / `emitTrail` 参数映射与上表的原生字段用途一致：普通发射第六项为寿命基值、第七项为阻尼、第八项为可选固定 split；轨迹第六项未使用、第七项为阻尼。
- #768/#770 的具体解释由压栈目标地址反转及函数后续对相应槽位的读取共同支持；这仍是静态分析，不表示参数已在原版运行时逐项探测。
- 静态反汇编没有证明原版的粒子画面、或从启动流程进入游戏的可用性；seed 结论限于上述可见初始化调用点，不替代原版运行证据。
