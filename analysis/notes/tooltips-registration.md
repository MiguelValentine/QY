# `RegToolTips` 桌面方法边界

本文记录 `objsys.dll` 桌面调用分派器中成员哈希 `0x2dc090dd` 的静态路径，以及 Go 侧可采用的保守对象边界。地址为 PE 装载基址 `0x10000000` 下的 VA。除该哈希已由原生 oracle 校验外，以下执行语义来自保存的反汇编，不代表原版运行时观察。

## 原生数据流

桌面成员调用分派器 `0x10060da0` 在 `0x1006140a` 比较成员哈希 `0x2dc090dd`。匹配时，`0x10061416–0x10061428` 要求实参 VM 值类型为 4；类型不符会离开该分支。随后 `0x1006142e–0x1006143f` 调 FBase #782，并把返回 DWORD 写入桌面对象 `+0x224`；FBase #782（`0x10001fa0`）在输入类型为 4 时返回 VM 值 `+8` 字段。

FBase #799 的已恢复值布局及 `pdesktop` getter 数据流表明，类型 4 值的 `+4` 保存对象标识，`+8` 保存宿主对象指针。因此这个分支登记/核验的是类型 4 值中的宿主对象指针，不应把 #782 返回值称为 `+4` 对象标识。

分派器随后调用 `objsys!0x1005ea10`（`0x10061441`）。该函数把桌面 `+0x224` 的 DWORD 作为键，调用 FBase #290；如果查找失败，则将 `+0x224` 清零。#290（FBase `0x1000b490`）读取其接收对象 `+8` 的条目数和 `+4` 的记录数组，对每项 8 字节记录中的首 DWORD 做二分查找，并以 `AL=1/0` 表示命中/未命中。由此可确认它是按 DWORD 键查找已登记项的布尔查询；记录第二个 DWORD 的语义仍未确认。桌面 `+0x1fc` 因而是该键表/注册表一类的结构，但其完整 C++ 类型和条目生命周期尚未恢复。

## Go 侧边界

当前 `Desktop.Windows` 是桌面工厂创建的 `Wnd` 集合；每个 `Wnd.Object` 可通过 `script.Object.Owner` / `Children` 关系连接到桌面根对象。它们提供比“接受任意 `Kind == "object"`”更严格的替代边界：

- 实参必须是非空对象，且对象指针必须等于该 `Desktop.Windows` 中某个非空窗口的 `Wnd.Object`。
- 若调用路径要求同桌面归属，再沿 `Owner` 检查该窗口对象能到达 `desktop.Object`，并拒绝空链、循环或其他根对象。
- 不能仅因对象的 `Owner` 链到达桌面就接受它；任意脚本对象也可能被挂到该树上，但并不在原生桌面键表中。也不能只按 `ClassName` 或通用对象类型接受，因为当前代码没有恢复原生注册键与这些字段的映射。

上述检查是 Go 侧的安全近似，不等同于原生 #290 的键表查询：当前结构没有单独保存原生 `+0x1fc` 的 DWORD 键映射。要做到逐语义对应，需要恢复窗口宿主指针/注册键的创建与注销路径；在此之前，未登记对象应拒绝，而不应默认成功。

## 返回与副作用

匹配分支只读取类型 4 VM 值的 `+8`，写入桌面 `+0x224`，再由验证函数按需清零；没有看到写回或重构输入 VM 值的调用。分支跳至公共出口 `0x10062470`，该处显式 `xor eax,eax`，所以原生分派器回调返回零；这个 EAX 值不能直接等同于脚本表达式的 VM 返回值。静态片段既未显示把原 VM 值复制到返回槽，也未显示改写输入值，因此“表达式沿用实参”尚不能确认。Go `CallMember` 应先将该分支视为副作用调用，不凭 EAX=0 或参数未改写推断脚本结果；在 VM 调用者的输出值规则恢复前，返回空值只是保守实现选择，不是已证实的原生语义。

`0x1006140a–0x10061446` 分支没有窗口显示/隐藏 API 调用，也没有写窗口可见性字段。不能由 `RegToolTips` 名称或 hash 候选推出它会隐藏窗口；可确认的副作用仅限桌面 `+0x224` 保存或清零该键值。

主要静态位置：`analysis/disassembly/objsys.annotated.asm` 的 `0x10060da0`、`0x1006140a–0x10061446`、`0x10062470`；`analysis/disassembly/fbase.annotated.asm` 的 #782（`0x10001fa0`）和 #290（`0x1000b490`）。Go 替代边界位于 `internal/objsys/desktop.go` 的 `Desktop.Windows`，`internal/objsys/wnd.go` 的窗口对象登记，以及 `internal/script/runtime.go`、`internal/script/object_tree.go` 的对象身份与所属树。
