# `:=` 绑定赋值的静态执行路径

## 范围与证据

本文追踪 `CLIENT/objsys.dll` 中 `SYSTEM.COD` 的 `bk := color(#003366);`，关注 FC0A 语句编译、执行分派、`color` 的角色、参数时序及返回值。依据为 `analysis/disassembly/objsys.asm`、FC0A 标记及 [SYSTEM 背景颜色笔记](system-background-color.md)。未运行原版程序；以下均为静态证据或明确标注的推断。

## 编译与执行分派

- FC0A 在偏移 `0x68–0x8c` 保存 `bk`、kind `1212`（`:='）、`color` 和整数 `0x3366`，语句来源及标记解释见 [SYSTEM 背景颜色笔记](system-background-color.md)。
- 编译器 `objsys!0x100101a9` 对 kind `0x4bc`（1212）和 `0x4d9` 分支到 `0x10010428`。该路径要求绑定目标类型为 6（`0x10010435–0x10010453`），随后解析其后的语法标记并构造执行节点。该解析函数内有将节点 `+4` 设为 `0x0e` 的路径（`0x10010790–0x10010794`）；执行器从节点 `+4` 选择跳表项（`0x10066032–0x10066045`），索引 `0x0e` 的分支入口为 `0x100678d4`。此处是编译节点与执行分支的静态对应，不是对运行结果的观察。
- `0x100678d4` 要求节点 payload 为容器类型 6、计数为 1；取其首项并检查为类型 4、内部计数为 2（`0x100678d4–0x1006791e`）。之后从表达式上下文取目标值，将其连同当前执行上下文、调用实参上下文和名称指针 `0x100a3d90` 传给 `0x1000a5d0`（`0x10067924–0x10067952`）。该调用返回 AL 状态；失败路径记录诊断并回到语句执行循环（`0x10067957–0x1006796b`），成功路径也在处理可选上下文后返回循环（`0x10067970–0x100679f0`）。

## `color` 是 selector 的判断

- 原生 `bk` 工厂、构造器及 vtable 链见 [SYSTEM 背景颜色笔记](system-background-color.md)：`bk` 对象首个 vtable 槽指向 `0x100435f0`。该分派器从调用帧 `[ESP+0x5c]` 读取哈希、从 `[ESP+0x60]` 读取值，并以哈希 `0x7d69d3c0` 进入 `color` 分支；整数值用于构造 RGB565 并写入对象 `+0xc4`。
- `0x100678d4` 的调用路径把表达式数据和实参上下文传入通用调用 helper `0x1000a5d0`，而不是在此处先把 `color` 作为独立数值表达式求值后再执行普通 `=`。结合 `bk` 的原生 hash 分派器，最符合静态证据的解释是 `color` 是绑定调用的名称/selector，`0x3366` 是交给该 selector 的实参。因 `0x1000a5d0` 之后的每个中间值尚未逐项追到 `0x100435f0`，这一点是强推断，尚非完整闭合的数据流证明。
- 对具体脚本，参数 `0x3366` 是字面整数，不含可产生副作用的子表达式；因此此例不存在可观察的多个参数间求值先后问题。执行器 opcode `0x0e` 分支从调用 payload 取出目标和调用信息后才调用 helper；静态代码没有显示它先独立执行一个全局 `color(...)` 再进行左值赋值。一般多实参表达式的精确顺序仍未在本笔记闭合。

## 返回值及边界

`0x1000a5d0` 的 AL 是调用成功/失败状态，opcode `0x0e` 分支据此继续或报告错误；控制流随后回到执行循环，没有在此分支将该 AL 或 `bk` handler 的内部状态写作脚本表达式结果。因此可证实的外部结果是绑定调用的副作用与执行状态，不是 `color` 产生一个可赋给 `bk` 的普通返回值。当前证据不证明所有 `:=` 绑定 handler 都无脚本返回值，也不覆盖可能由其它节点形式消费调用结果的路径。

## 移植注意

Go 实现应把这种 `:=` 形式与普通赋值及一般全局函数调用分开处理：解析左侧接收对象和成员哈希，保留 RHS 调用名称作为 selector，并只求值其实参，再交给宿主对象的绑定/调用入口。对 `bk := color(0x3366)`，宿主处理应验证 `color` selector 和整数参数，再更新背景状态；不应调用同哈希的全局函数并把普通返回值写入 `bk`。具体 handler API 和失败策略属于移植设计，不是原生静态分析直接给出的 ABI。
